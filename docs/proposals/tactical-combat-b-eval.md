# 戰鬥戰術化（方案 B／B3）的技術與設計評估（2026-11-04）

回應使用者與 ChatGPT 整理的「戰鬥系統提案：戰術化戰鬥與野外知識判讀」（以下稱「B 提案」）。這份只做評估：可以重用什麼、要改什麼、風險、成本、替代做法，以及需要使用者先回答的問題；**還不是規格**。前一份比較是 `docs/proposals/tactical-combat.md`（A～D）。標【假設】的是 Claude Code 的推測。

## 零、總結

- **B 提案的方向做得到**，而且現有程式能重用的比預期多：戰術狩獵已經有格子地圖、移動範圍、喘（短衝的本錢）、面向與轉身、角度（後／側／正面）、帶因素的機率、反擊風險、同伴 AI、避難處（洞口、峭壁）、依感知顯示的「意圖範圍」（這就是部分預告的雛形）。選單式戰鬥已經有「先後與打斷」（Phase 1.9，雙方同一回合出手時誰先）、威嚇三段、試探（看出牠堅定還是動搖）、受傷部位、放棄的門檻。知識系統已經有分次累積（0～3 次到「確定」）。
- **要新做的核心**只有三塊：(1) 預告與同步結算的回合流程；(2) 以資料描述的物種動作與 AI；(3) 「行為知識」影響資訊品質。
- **最大的風險不在程式，在可讀性與美術**：同步結算容易讓玩家覺得「不公平」；部分預告需要看得出來的動作（抬掌、伏低），正式版每種動物每個動作都要有預備動作的圖。
- **成本【假設】**：第一階段原型（灰熊、美洲獅、搶食、預告、同步結算）約 2.5～3.5 週；接進主遊戲（取代這兩種的選單式戰鬥、結果、成長、自動玩家、一生模擬重新校準）約 1.5～2 週；第二階段（黑熊、狼對狼、同伴、圍剿、守巢）約 3～4 週。合計約 7～9 週，比 D 多出約一半，多出的部分主要是預告系統、物種 AI 與重新校準。

## 二、B3（同步決策、移動＋攻擊組合、部分預告）需要的調整（問題 2）

現在的戰術狩獵是**輪流**：狼行動 → 鹿行動 → 更新。B3 要改成：

1. **回合開始：對手先「表態」**。對手照 AI 選好這回合要做的事（例如揮掌），畫面依資訊品質顯示預告（明確／部分／模糊，見第五節）。
2. **玩家決策**：移動＋一個動作（第三節）。
3. **同步結算**：雙方的移動與動作一起算。誰先由「先後」規則決定（Phase 1.9 已經有：速度、動作種類、距離）。
4. **事件序列播放**，進下一回合。

關鍵設計（建議）：**攻擊打的是「範圍」，不是「目標」**。灰熊揮掌打的是牠正面的幾格；你這回合往側面閃，就在範圍外。這樣同步結算才看得懂（玩家看到範圍、決定站哪裡），不會變成擲骰子；也是戰術遊戲常見的做法。

**假動作與改變心意**：對手表態後，有一定機率在結算時換成別的動作（虛張聲勢的衝撞、臨時撤退）。機率依物種與狀態（灰熊守食物時常假衝）。這保留「看提示不一定對」。

要動到的程式：
- 新的戰鬥邏輯類別（建議 `TacticalCombat.gd`，和 `TacticalHunt.gd` 共用地圖、移動、角度等工具函式；先把這些抽成共用的模組，狩獵不受影響）。
- 對手的動作與表態資料（第四節）。
- 結算：把 Phase 1.9 的先後規則從「選單動作」改成「地圖上的動作＋範圍」。
- 畫面：預告的圖示與範圍、同步結算的播放。
- 結果接回主遊戲：受傷、食物、成長（第一次打贏）、知識、一生回顧，現在 `Combat` 的結局都要對上。

**替代做法（如果同步結算試玩起來太亂）**：「預告後輪流」。對手先表態，玩家行動，對手再照表態執行（有機率改變）。實際上效果接近同步，但比較好懂、比較好寫。原型可以兩種都做來比較。

## 三、行動成本（問題 3）

建議沿用戰術狩獵已有的資源，不另外發明「行動點數」：

- **每回合：移動額度＋一個主要動作。**
  - 移動：小跑距離內不花喘；超過就是衝刺、花喘（現在的規則）。
  - 主要動作：咬、撲、叼一塊、威嚇、騷擾、閃避（擇一）。
  - 「移動後攻擊」可以，但移動越遠，這一下的機率越低、被反擊的風險越高（現在的撲咬已經分「站定撲」和「跑過去撲」）。
  - 「閃避」用掉主要動作：這回合不能攻擊，換到被打中的機率大降、可以多退一格。
- **喘**是一場戰鬥裡的短期資源（衝刺、閃避、連續撲咬都花喘），**體力**是結束時一次結算的長期代價（同狩獵）。
- 不建議 3 點、4 點的行動點數：多一層要算的數字，和狩獵不一致，選擇卻沒有多。

【假設】這樣每回合的決策是「站哪裡」＋「做什麼」兩件事，灰熊一場約 8～15 個回合。

## 四、物種差異化的 AI（問題 4）

共用一套框架，物種只是資料：

- **動作庫（共用）**：揮掌、衝撞、虛張聲勢的衝撞、撲擊、咬、站定、守食物、後退、轉身、爬樹／上石頭、逃跑、威嚇。每個動作有：範圍（哪幾格）、預備時間（有沒有預告、預告多明顯）、恢復時間（出手後的空檔）、傷害、對面向的要求。
- **物種資料**（放在 JSON，像現在的 `tactical_hunt.json` 的物種設定）：
  - 能用哪些動作、各自的權重。
  - 轉身速度、移動速度、追擊的耐力。
  - 假動作的機率、預告的清楚程度（美洲獅的預告比灰熊模糊）。
  - 什麼情況下會放棄、爬樹、守食物（利害、血量、數量、地形）。
- **AI**：每回合替每個可用動作打分（距離、角度、血量、利害、對方數量、附近有沒有樹或岩壁），照分數加一點隨機選一個。只有「爬樹後的圍困」「守食物」需要少量專用程式。
- 個體差異【假設】：同一種動物有個性（大膽／謹慎），改變權重，避免玩家背熟一種打法。

## 五、知識影響資訊品質（問題 5）

B 提案的方向（知識影響「看得多清楚」，不是命中率）和現有的設計一致：試探看出「堅定／動搖」、意圖範圍隨感知縮小，都是資訊而不是加成。

建議的對應：

| 資訊 | 誰影響 | 低 → 高 |
| --- | --- | --- |
| 預告的清楚程度 | 行為知識＋感知；距離、視線遮擋、夜晚會降低 | 模糊（「牠在蓄勢」）→ 部分（「牠要攻擊」）→ 明確（「抬起前掌，要揮掌」） |
| 認得假動作 | 行為知識（這種動作見過幾次） | 看不出來 → 「牠可能只是嚇你」 |
| 對手的狀態 | 實戰經驗 | 看不出 → 「牠累了」「牠動搖了」（現在的試探） |
| 機率的精確度 | 實戰經驗 | 範圍（「約 30～50%」）→ 精確數字 |

**知識從哪來**（多數已經有事件可以掛）：
- 遠遠看到牠做這個動作：灰熊遠距目擊、黑狼遠距觀察、看灰熊搶食。
- 痕跡：抓痕、熊的臥窩、美洲獅的藏食（灰熊藏食剛做完）。
- 實際交手：見過、躲過、被打中。
- 新的知識種類【假設】：`behavior|灰熊|揮掌`、`behavior|灰熊|虛張聲勢` 這種「物種＋動作」，沿用現在的分次累積（0～3）。

**要避免的**：
- 知識的好處看不出來。要在畫面上寫出來（「你認得這個動作」），一生回顧也可以列「學會讀懂的動物」。
- 玩家自己記住了，狼卻不知道。畫面只顯示狼知道的；但玩家記得「灰熊常假衝」這件事擋不住。用個體差異與假動作的隨機，讓背答案不夠用。

## 六、個體知識與家族知識的資料架構（問題 6）

- 現在的知識存在 `GameState.knowledge`（一個字典，一局只有一隻狼），種類有：獵物出沒、危險、弱點、過度獵捕、陌生的狼、地盤、鄰群的地方、對手。
- 建議現在就做的小調整（不影響玩法）：每一條知識加兩個欄位。
  - `category`：`experience`（實戰）、`lore`（習性）、`place`（地方與探索）。
  - `source`：`self`（自己經歷）、`family`（傳承來的，之後才會用到）。
- 之後要做傳承時：新的一隻狼開局時複製 `lore` 的一部分（例如降一級）、`place` 全部或部分，`experience` 不複製。
- **要注意**：Phase 3 的決定是「死後照舊結束」，沒有接著玩後代。家族知識要等使用者決定做傳承才有用；現在只預留欄位。

## 七、第一階段的原型（問題 7）

同意 B 提案：灰熊、美洲獅、搶食。建議做成固定情境的原型（同戰術狩獵原型的做法），每個情境可以重複玩、模擬：

1. 你的馬鹿殘骸，灰熊走過來（守住、退開觀望、咬一塊撤退、攻擊）。
2. 灰熊趴在殘骸上（繞過去、趁牠轉身叼一塊）。
3. 開闊地撞上灰熊（虛張聲勢的衝撞、真的衝撞；退開還是站住）。
4. 美洲獅守著藏起來的鹿，旁邊有樹和岩壁（美洲獅轉身快、預告模糊）。
5. 美洲獅伏擊（在旁邊開場）。
6. （加分）情境 1 加上伴侶：一隻牽制、一隻叼肉。

驗證：固定打法的模擬（一直正面、一直繞後、搶了就跑、一直閃）各 200 場以上；使用者試玩。通過標準沿用 `tactical-combat.md` 第六節，加上「預告：知識高的狼被假動作騙到的比例明顯較低」。

## 八、低威脅遭遇（問題 8）

- 紅狐、郊狼、猞猁、狼獾，以及「實力差很多」的遭遇（成年狼對狐狸）：維持選單式，或直接結算。
- 遠距離發現時，先在進地圖前讓玩家選「退開」，不用每次都進戰鬥。
- 每場都有「交給本能」。
- 【假設】設定裡可以選「戰鬥：戰術／快速」，快速時重要的戰鬥也用選單式（給不想操作的玩家）。

## 九、風險

1. **同步結算的「不公平感」**：玩家照預告閃開卻被打中，會覺得被騙。對策：範圍式攻擊、假動作有跡可循（知識）、結算後清楚播放「牠改變了動作」。
2. **美術**：部分預告靠看得出來的姿勢。佔位階段可以用圖示＋文字；正式版每種動物每個主要動作都要有預備姿勢與出手的圖，工作量比狩獵大很多。
3. **戰鬥變長**：每場 8～15 回合，加上一生裡遇到的次數，總時間會增加。靠「交給本能」、低威脅不進地圖、遠距先退來控制。
4. **重新校準**：取代選單式戰鬥後，勝率、受傷、壽命、餓死都要重跑模擬；回歸測試裡跟 `Combat` 有關的要改寫（`combat_sim`、`encounter_matrix` 的一部分等）。
5. **兩套回合規則**：狩獵是輪流、戰鬥是同步，玩家要適應兩種節奏。可以接受（一個是追獵、一個是對峙），或之後讓狩獵也加入預告。
6. **範圍膨脹**：B 提案的願望很多（物種、知識、傳承、群戰）。照兩階段，第一階段只做灰熊、美洲獅、搶食、預告，做完先試玩再決定。

## 十、和方案 D 的關係

D 的第一階段（位置、角度、食物、撤退）是 B 的子集；B 多的是「預告＋同步結算」「物種動作與 AI」「行為知識」。如果擔心成本，可以**先做 D 的第一階段，再把預告與同步結算加上去**，一樣能走到 B，而且每一步都能試玩。這和直接做 B 的第一階段差約 1 週。

## 十一、需要使用者先回答的

1. **同步結算還是「預告後輪流」**：原型兩種都做來比較，可以嗎？
2. **機率顯示**：知識低時顯示範圍（「約 30～50%」）、高時顯示精確數字，可以嗎？還是一律顯示精確數字？
3. **第一階段要不要包含伴侶**（情境 6）？B 提案把隊友 AI 放第二階段，但「一隻牽制、一隻叼肉」是搶食最有代表性的畫面。
4. **家族知識**：現在只在資料上預留欄位、不做傳承，對嗎？（Phase 3 的決定是死後照舊結束。）
5. **預告的美術**：原型用圖示＋文字代替姿勢，可以嗎？
6. **直接做 B，還是先做 D 的第一階段再加預告**（第十節）？
