# 提案：用嚎叫找伴侶（嚎叫回應與循聲而去）

2026-11-23。起因：使用者試玩時幾乎每天嚎叫、到處標記地盤，只遇到一次離群的母狼，也沒有配對成功。覺得遇到的機率太低，而且「嚎叫」做了也看不出有沒有用。使用者的構想：你嚎叫時，附近有可以配對的母狼就會嚎叫回應；你聽聲音的方向過去，到了再嚎叫一次更容易找到牠；可以有「循著嚎聲而去」的選項；有時候好幾個方向都有狼嚎回應，要自己選往哪裡走。（使用者提到另一款狼的遊戲有類似的做法，這裡只參考「嚎叫 → 回應 → 循聲」的概念。）

這份提案寫給使用者，也寫給沒有專案背景的人（例如 ChatGPT）。依專案的協作原則，這是**影響玩法的規則**，先列方案、使用者選定後才寫規格。

---

## 1. 背景（給第一次看的人）

《狼之一生》是單機生存養成遊戲，玩家扮演一隻北美灰狼，從 8 個月大活到死亡。地圖分成幾張（森林、苔原、山地、草原……），每張有 4～6 個區域；一天分成幾個時段，每個時段可以做幾個行動（探索、狩獵、休息、標記地盤、嚎叫……）。一季 10 天，一年 40 天。2 歲成年後可以找伴侶、成家、生幼狼（Phase 3）。

**目前的配對流程**（`data/balance.json` 的 `mate`、`GameState` 的 `_update_she_wolf`、`action_howl`）：

1. **出現**：成年、沒有伴侶時，每天換日擲一次。秋冬每天 1.5%、春夏 0.3%；前一天嚎叫過 ×3、標記過 ×1.5、這一區獵物沒被獵少 ×1.2。出現時先跳一張「徵兆」（聞到氣味或遠遠看到），寫出牠在哪一區（你所在的區域或相鄰區）。
2. **找到牠**：牠每天 30% 走到相鄰區。你在牠那一區探索時 30% 遇上；你嚎叫時，牠在同一區或相鄰區的話 50% 循聲找來。
3. **累積關係到 9**：走近、跟著、一起吃各 +1，分牠一段肉、一起狩獵成功 +2；搶牠的食物 −3、示弱或撤退 −1。7 天沒見之後每天 −1，而且每天 25% 離開。
4. 另外：苔原那對苔原狼只剩母狼、關係友善時，換季 50% 留下來成為伴侶。

**現在的數字**：
- 每天黃昏嚎叫、又標記地盤，秋冬每天約 8%（1.5% × 3 × 1.5 × 1.2），春夏約 1.6%。一年大約遇到 1 次；什麼都不做約 0.3 次。
- 自動玩家的模擬（認真找）成年後 1 年內配對約 80%，但那是「知道規則、每天做對」的自動玩家；玩家看不到牠在不在、嚎叫有沒有作用。

**問題**：
- 「嚎叫」在牠還沒出現時，只是讓隔天的機率變 3 倍，畫面上什麼也沒發生，玩家感覺不到。
- 出現是看不見的擲骰；找不到時不知道是運氣差、還是做錯了。
- 出現之後要「待在牠那一帶、7 天內一直見到牠」，但沒有線索告訴你牠走到哪裡。

**現有可以接上的系統**：
- 夜裡會聽到黑狼、黑狼一家、地圖上鄰近狼群、苔原狼的嚎叫（`neighbor_howl` 事件），文字會分「一隻／好幾隻」「從哪一邊傳來」。
- 地圖的區域有相鄰關係；各區有方向（北、南……），之前做過「遠處的煙」寫出方向。
- 撞上狼群（退開、對峙、逃）、和黑狼對峙、單挑都已經有。

---

## 2. 設計目標

- **嚎叫是一個看得到回應的行動**：嚎了就有結果（有回應、沒有回應），回應帶有方向與聲音的特徵。
- **找伴侶是一段小小的旅程**，不是擲骰：聽 → 判斷 → 過去 → 再嚎 → 遇上。
- **有判斷、有風險**：好幾個方向都有回應時，一隻的聲音、一群的合聲意義不同；跟錯了可能撞上狼群。
- **不要變成必然**：認真找的玩家一個秋冬內大多能遇上，但配對仍要經營關係；不找的玩家偶爾也會遇到。
- 照生態（見第 6 節），秋冬是離群的狼四處遊走、找伴侶的季節。

---

## 3. 方案

### 方案 A：嚎叫回應＋循聲而去（使用者的構想，完整版）

**牠們本來就在世界裡**：
- 秋冬（擴散的季節）每張地圖常態有 0～2 隻離群的狼在遊走（母狼為主，也可能是離群的公狼、年輕的狼）。換季時重新擲；春夏少。
- 牠們不再「突然出現在你身邊」，而是在離你 1～2 個區域外走動，等你找到。

**嚎叫 → 回應**：
- 你嚎叫時，這張地圖上聽得到的狼會回應（照距離：同區、相鄰區一定聽得到，兩區外有機率）。
- 每個回應寫出**方向（或區域）與聲音的特徵**：
  - 離群的母狼：「一隻狼的聲音，悠長、遲疑，從東邊的溪谷傳來。」
  - 鄰近的狼群、黑狼一家：「好幾個聲音一起回應，又低又急，從北邊的林子傳來。」（這是警告：那裡是牠們的地方）
  - 那隻黑狼：一隻、帶著挑釁（認得牠之後寫明是牠）。
  - 苔原狼：照現有的關係文字。
- 好幾個方向同時有回應時，全部列出來。也可能一個回應都沒有（附近沒有狼，或牠們沒出聲）。
- 回應的文字只描述聽到的，不直接說「這是可以配對的母狼」；玩家從「一隻、悠長」去判斷。

**循著嚎聲而去**：
- 嚎叫有回應後，行動欄多出「循著嚎聲而去（往東邊的溪谷）」，每個回應一個選項（最多 3 個）。選了就往那一區走一格（照一般移動的時間與體力）。
- 回應的「記憶」維持到這個時段或下一個時段結束；牠也在走動，越晚去越可能已經走開。
- 到了那一區：
  - 探索時遇到牠的機率大幅提高（例如 30% → 60%）；
  - 再嚎叫一次，牠在這一區或相鄰區時大概率回應並走過來（現有的「循聲找來」改成更高，例如 50% → 75%），或回應告訴你牠又往哪裡去了。
- 跟著的是狼群的合聲：到了那一區撞上狼群的機率提高（牠們在告訴你這裡有主）。
- 往黑狼的方向：照現有的黑狼規則（可能對峙）。

**關係的維持**：
- 「7 天沒見」改成：見過牠之後，牠會在附近遊走；你嚎叫時牠會回應（關係越好越常回應），讓你找得回牠。

**遊玩感受**：嚎叫有立即的回饋，找伴侶變成「聽、選方向、去、再嚎」的小探索；好幾個方向時要判斷聲音，選錯了撞上狼群，有風險也有故事。
**代價**：工作量最大。要做離群狼的常態存在與遊走、嚎叫回應的判定與文字、行動欄的循聲選項、自動玩家、一生模擬、回歸測試。文字量中等（各種聲音 × 方向）。
**對其他系統的影響**：
- 鄰近狼群、黑狼一家「被你的嚎叫引出來」：撞上狼群的機率會因為玩家常嚎叫而變高，要校準（現有的「嚎叫的那天撞上黑狼一家 × 1.5」改成透過循聲去觸發）。
- 世界裡常態有離群的狼，之後也可以是「離群的公狼來挑戰你」「加入你狼群的年輕狼」（Phase 3 已有加入的機制）的來源。
- 自動玩家要學會：嚎叫 → 挑一隻的聲音 → 跟過去 → 再嚎。

### 方案 B：嚎叫回應（輕量版，不加「循聲而去」）

- 出現的方式不變（每天擲骰），但**機率提高**：例如秋冬 1.5% → 4%，嚎叫 ×3 不變（每天嚎叫、標記約 20%／天，一個秋冬幾乎一定出現）。
- 牠出現之後，你嚎叫時牠**一定回應**（在同一張地圖上），文字寫出牠在哪一區；牠在同一區或相鄰區時照現有的 50% 走過來。
- 鄰近狼群、黑狼在附近時也會回應（合聲），作為干擾。
- 沒有新的行動選項，玩家照回應的方向自己移動過去。

**遊玩感受**：嚎叫有回饋、找得到牠在哪，但少了「選方向、跟過去」的決定。
**代價**：小。只改出現機率、嚎叫的回應文字與判定。
**對其他系統的影響**：小；一生模擬的配對時間會提早。

### 方案 C：擴散的季節（事件型）

- 秋末到冬天的某幾天是「擴散的季節」：夜裡會聽到遠處有離群的狼在嚎叫（不用你嚎叫，自動出現的事件），寫出方向。
- 你可以選「回應牠的嚎叫」或「循著聲音去」；循著聲音去就和方案 A 一樣，到了那一區提高遇到的機率。
- 平常日子的出現機率維持低。

**遊玩感受**：有季節感、像故事事件；但玩家主動嚎叫的作用仍然不明顯，而且是「等事件」不是「主動找」。
**代價**：中。新事件、循聲的流程。
**對其他系統的影響**：中；和夜裡的狼嚎事件（黑狼、鄰群）共用文字與時機。

### 比較

| | A 完整版 | B 輕量版 | C 擴散的季節 |
| --- | --- | --- | --- |
| 嚎叫有立即回饋 | 有 | 有（牠出現之後） | 部分（事件來時） |
| 選方向、跟過去的決定 | 有（好幾個方向） | 沒有（自己走） | 有（事件來時） |
| 風險（跟錯撞上狼群） | 有 | 少 | 有 |
| 工作量 | 大（約 4～5 步） | 小（約 1 步） | 中（約 2～3 步） |
| 對世界的影響 | 世界裡常態有離群的狼 | 只改機率 | 季節事件 |

**Claude Code 的建議**：A，但分階段做——先做「嚎叫回應＋循聲而去」的最小版本（只有離群的母狼與鄰近狼群會回應），試玩確認好玩，再補離群的公狼、黑狼、苔原狼的回應與自動玩家的完整策略。A 的核心正好也滿足 C 的季節感（離群的狼秋冬多、春夏少）。

## 4. 方案 A 的最小可玩版本（如果選 A）

1. **離群的狼在世界裡**：秋冬每張地圖 70% 有一隻離群的母狼在遊走（離你 1～2 區外出現），春夏 20%；牠每天 30% 換到相鄰區（現有）。
2. **嚎叫回應**：你嚎叫時，同區、相鄰區的狼一定回應，兩區外 50%；母狼「一隻、悠長」，鄰近狼群「好幾隻、低沉急促」。文字寫出方向與區域名稱。
3. **循著嚎聲而去**：嚎叫後行動欄每個回應一個「循著嚎聲而去（往 X）」，走到那一區；在那一區遇到母狼的機率 30% → 60%、嚎叫時牠走過來 50% → 75%；跟著狼群的聲音過去，撞上狼群的機率提高。
4. **一生模擬與回歸測試**。

數值都是初始值（Claude Code 的假設），試玩與模擬校準。

## 5. 假設、驗證方式、通過標準

- **假設**：嚎叫有回應、可以循聲而去之後，玩家會主動用嚎叫找伴侶，而且覺得找到牠是自己的判斷與行動，不是運氣。
- **驗證**：
  - 模擬（自動玩家改用「嚎叫 → 挑一隻的聲音 → 跟過去 → 再嚎」）：成年後第一次遇上的天數、配對的天數、跟錯方向撞上狼群的次數；
  - 試玩：一個秋冬內玩家能不能遇上；好幾個方向時會不會去判斷聲音。
- **通過標準（初始值，請使用者確認）**：
  - 認真找（秋冬每天嚎叫、跟著回應走）的玩家，一個秋冬（20 天）內遇上離群母狼 ≥ 80%，平均 5～8 天；
  - 遇上後 1 季內配對 50～70%（關係仍要經營）；
  - 不找的玩家一年內遇上約 30～50%（偶爾還是會碰到）；
  - 嚎叫有回應的比例：秋冬 ≥ 60%，春夏 30～50%（不是每次都有）；
  - 跟著狼群合聲走的那幾次，撞上狼群 ≥ 40%（選錯有後果）；
  - 一生模擬的挨餓、壽命不惡化（找伴侶花的時間不會讓狼餓死）。

## 6. 生態依據（Claude Code 依記憶整理，未逐條查證，討論時請一併確認）

- 北美灰狼的離群（dispersal）多在 1～3 歲，秋天到初冬、以及冬末繁殖季前最常見；離群的狼會遊走很遠找空的領域與伴侶。
- 嚎叫是狼群之間、狼與狼之間遠距離定位的主要方式；狼群的合嚎常有宣示領域、警告的意味。
- 離群的狼為了避開領域狼群，常常比較少主動嚎叫，但會回應遠處的單隻嚎叫；狼群聽到陌生的嚎叫，有時回應、有時循聲過來驅趕。
- 灰狼的交配季在冬末（約 1～3 月），配對多在交配季之前形成。

## 7. 想請教的問題（給 ChatGPT 或使用者）

1. A、B、C 哪一個最符合「玩家透過狼的視角學會在野外生存」的方向？A 的分階段做法合理嗎？
2. 回應的文字要多明確？只寫「一隻、悠長」讓玩家自己判斷，還是第一次聽到時加一句提示（例如知識頁「離群的狼常常只回應一兩聲」）？
3. 好幾個方向同時回應時，最多列幾個比較好？選錯撞上狼群的風險要多大，才不會讓玩家不敢嚎叫？
4. 離群的母狼常態存在之後，「7 天沒見就離開」要保留嗎？還是改成「牠會在附近遊走，嚎叫時回應」，讓關係比較好維持？
5. 是否也讓離群的**公狼**回應（可能是競爭者、也可能之後加入你的狼群）？會不會讓找伴侶太複雜？
6. 嚎叫會不會被濫用（每個時段都嚎）？要不要限制一天幾次、或嚎太多次讓獵物警覺、引來黑狼？

## 8. 不在這次範圍

- 伴侶的關係經營、成家、育幼的規則（Phase 3）不改，只改「怎麼找到牠」。
- 聲音的實際音效：目前只有文字；之後有音效時，回應的聲音（一隻、合聲）可以直接用聽的分辨。

# 決定與 Phase 1 實作規劃（2026-11-24）

## 使用者與 ChatGPT 討論後的決定（摘要）

- 採用 **A：嚎叫回應＋循聲而去**，分三個階段；這次只規劃 **Phase 1**。
- 嚎叫是**環境感知與探索的工具**，不是找母狼的 GPS：回應給大致方向、遠近、聲音特徵、一隻或一群的初步判斷，**不說身分**；一次最多 3 個回應來源。
- 循聲過去**不保證遇到**：可能遇上、聞到氣味、看到足跡、牠已經走了、再嚎得到更近的回應、發現狼群領域的痕跡。
- 限制與風險：**時段不同、回應率不同**；**嚎叫會暴露自己的位置**（依附近的狼與領域決定，不是每次固定觸發）。**不設冷卻、不設「同一區重複嚎叫情報變少」**。
- 取消「7 天沒見就離開」；離群的狼有自己的活動狀態。
- 季節：春夏少但仍可能遇到，秋季增加，冬季找伴侶動機最明顯，冬末到春季是配對的重要時期。
- 狼群的嚎叫不一定友善；循聲接近狼群時，要先有機會透過氣味、抓痕、足跡察覺，再決定要不要深入。
- 測試目標沿用：認真找的玩家一個秋冬內遇上 ≥ 80%、遇上後一季內配對 50～70%、不找的玩家一年內 30～50%；循聲接近狼群的遭遇率要測試，不能是單純懲罰、也不能毫無風險。

## 1. Phase 1 要改的系統

| 系統 | 現在 | Phase 1 改成 |
| --- | --- | --- |
| 離群母狼的出現（`GameState._update_she_wolf`、`_spawn_she_wolf`） | 每天擲骰，出現在你身邊或相鄰區，跳一張徵兆卡 | 照季節決定這張地圖上「有沒有一隻離群母狼在遊走」，出現在離你 1～2 區的地方，**不跳徵兆卡**（要靠嚎叫、探索才知道） |
| 母狼的離開 | 7 天沒見之後每天 −1、25% 離開 | 取消。改成「牠也在找」：每天低機率離開這張地圖（照季節與關係，見第 3 節），關係好的不太走 |
| 嚎叫（`action_howl`） | 母狼在同區或相鄰區 50% 走過來；只回傳有沒有來 | 回傳一串回應（最多 3 個）：來源、區域、遠近、一隻或一群、聲音特徵；母狼在同一區時照舊可能直接走過來 |
| 嚎叫的風險（`_howl_meet_mult`） | 嚎叫的那天撞上黑狼一家 × 1.5（固定） | 改成「被察覺」：在狼群的地方或旁邊嚎叫，那一群在接下來幾個時段知道你在附近，在牠們那一帶撞上的機率提高，在牠們的領域裡可能直接循聲過來 |
| 循聲而去（新） | 沒有 | 嚎叫有回應後，行動欄多「循著嚎聲而去（往〇〇那一帶）」，每個回應一顆，走到那一區；回應的記憶維持到下一個時段結束 |
| 探索（`action_explore` 的發現順序） | 母狼在這一區時 30% 遇上 | 循聲到達的那一區（記憶還在時）：照實際情況出現不同的結果，見第 2 節 |
| 文字（`localization`） | 母狼的徵兆、相遇 | 嚎叫的回應（一隻／一群 × 遠近 × 時段的氣氛）、沒有回應、循聲的按鈕、到達後的線索（離群狼的足跡與氣味、狼群的標記與抓痕）、被察覺的提示 |
| 自動玩家（`AutoPlayer` 的 `mate_search`） | 黃昏嚎叫一次；always 時標記 | 嚎叫 → 挑一隻的回應 → 循聲 → 探索或再嚎；聽到合聲時不跟（或跟到邊界看到標記就回頭） |
| 除錯選單 | 「離群的母狼」「母狼的關係 +4」 | 保留；「離群的母狼」改成放在離你兩區外（測試循聲） |
| 一生模擬（`life_pressure`）、配對模擬（`mate_search`） | 有 | 加嚎叫、回應、循聲的統計 |

不改：伴侶的關係經營（走近、一起吃、分肉、一起狩獵）、成家、育幼；苔原狼的配對路線；黑狼的單挑。

## 2. 離群母狼、狼群的回應如何接上現有系統

**誰會回應（Phase 1）**：
- **離群母狼**（還沒成為伴侶的那一隻，`mate_stage == "candidate"`）。
- **鄰近狼群**：現有的鄰群（`balance.packs.layout`：森林外圍〔地圖外，在森林西部那一側〕、山地、草原、草原外圍）。地圖外的狼群用牠們邊界那一區當成聲音的方向。
- **黑狼一家**：見「需要確認的事項」第 1 題（森林裡除了地圖外的鄰群，就是黑狼一家）。
- 苔原狼、那隻黑狼（單獨時）、離群公狼：Phase 1 不回應（Phase 3）。

**回應的資訊**（只給聽得到的）：
- **方向**：用區域名稱表達「從〇〇那一帶傳來」。地圖資料沒有東西南北，現有的夜裡狼嚎、遠處的煙也都是寫區域，照這個做法（見確認第 2 題）。
- **遠近**：同一區或相鄰區「很近」、兩區外「遠遠的」、地圖外「從地圖邊緣再過去」。
- **一隻或一群**：離群母狼是一隻；狼群照牠們的隻數，2～3 隻「兩三個聲音」、更多「好幾個聲音」。
- **聲音特徵**：一隻的悠長、斷續、試探；一群的低沉、連續、此起彼落。只描述聲音，不說是誰、也不說牠的意圖。第一次聽到時，知識頁記下「一隻狼的嚎聲可能是離群的狼，也可能是走散的成員」這類觀察（不是答案）。
- 回應最多 3 個，照「越近越先」挑。

**循聲到達後**（記憶還在、在那一區探索時；每次探索擲一次，不是全部出現）：
- 回應的是**母狼、牠還在這一區**：遇上的機率 30% → 60%（初始值）；沒遇上時有機會看到牠新鮮的足跡或氣味（「一隻狼的足跡，很新，往〇〇去」）。
- **母狼已經走到相鄰區**：有機會看到往那裡去的足跡；在這裡再嚎叫，牠的回應會變成「很近」。
- 回應的是**狼群**：先出現的是牠們的標記、抓痕、密集的氣味（現有的 `pack_sign` 卡片，到了牠們的邊界就有機會看到），讓你知道這裡是牠們的地方；**再往牠們的領域裡走**，撞上的機率才明顯提高。
- 什麼都沒找到也可能（牠移動了、你錯過了）。

**沒有回應**：文字是「四周一片安靜，沒有聲音回來。」——不代表附近沒有狼（牠們可能沒出聲）。

## 3. 回應率、季節、時段、風險的初步設計（全部是初始值，Claude Code 的假設，模擬與試玩校準）

**離群母狼在不在這張地圖上**（換季時擲一次；不在時，每天再擲一個小機率「走進這張地圖」）：

| 季節 | 換季時在的機率 | 不在時每天走進來 | 在時每天離開 |
| --- | --- | --- | --- |
| 春 | 25% | 1% | 5%（關係 ≥ 熟悉時 1%） |
| 夏 | 20% | 1% | 5%（1%） |
| 秋 | 60% | 4% | 2%（0.5%） |
| 冬 | 75% | 5% | 2%（0.5%） |

- 牠每天 30% 走到相鄰區（現有），遇到狼群的領域會轉向（不走進狼群的核心區；Phase 1 只做這一條簡單的避開）。
- 牧場地圖不出現（現有）。

**回應率**（每個可能的回應者各擲一次）：

| | 同一區、相鄰區 | 兩區外 | 地圖外 |
| --- | --- | --- | --- |
| 離群母狼 | 60% | 30% | — |
| 狼群 | 55% | 30% | 25% |

- **時段倍率**：清晨 1.0、白天 0.4、黃昏 1.0、夜裡 1.2、黎明前 0.9。
- **季節倍率**：母狼 春 0.8、夏 0.7、秋 1.0、冬 1.2（冬季找伴侶的動機最明顯）；狼群 夏 0.8（育幼期守在巢穴附近、比較安靜）、其他 1.0。
- **關係**：見過、關係熟悉以上的母狼回應率 +0.2（牠認得你的聲音）。
- 母狼在你**同一區**時，照現有的「循聲走過來」（50%，關係好時更高），直接變成相遇。

**風險：暴露自己的位置**（依實際的狼與領域，不是每次嚎叫都觸發）：
- 你在某一群的**邊界**嚎叫：那一群「察覺」你，接下來 4 個時段在牠們那一帶撞上的機率 × 2。
- 你在某一群的**領域裡**嚎叫：× 3，而且 30% 牠們直接循聲過來（撞上狼群：現有的退開、對峙、逃）。
- 離牠們兩區以上：沒有影響。
- 取代現在固定的「嚎叫的那天撞上黑狼一家 × 1.5」。和伴侶一起時的「一起嚎叫 × 0.6」保留（兩隻狼的聲音，牠們比較不敢來）。

## 4. 怎麼避免嚎叫變成要一直按的最佳解

不用冷卻、不降低重複嚎叫的情報，靠自然的成本與世界本身：
1. **時間與體力**：嚎叫花一回合、體力 2（現有）。白天嚎叫回應率只有 0.4 倍，晨昏、夜裡才划算——玩家會自然挑時機。
2. **世界不會因為你多嚎幾次而改變**：離群母狼一天大約只移動一次，同一個時段連嚎三次，聽到的還是同一個方向；要得到新的資訊得**動身**過去。這是自然的遞減，不是系統懲罰。
3. **暴露的風險會累積在實際的地點**：在狼群附近一直嚎，牠們一直知道你在哪裡。
4. **回應只是方向**：真正的收穫在循聲過去之後的探索，嚎叫本身不給獎勵。
5. 量測時會看「每天嚎叫幾次」與成功率的關係：如果每天嚎 5 次以上明顯比 1～2 次好很多，就是有問題，回頭調整（例如回應率或世界的移動）。

## 5. 要新增的測試與驗證方式

- **規則測試 `howl_reply_rules`**（headless，每次改動都跑）：
  - 回應者只有離群母狼與鄰群（Phase 1）；最多 3 個；越近越先；
  - 回應的文字不含身分（不出現「母狼」「離群」「黑狼」等字）；
  - 時段倍率：同樣的局面，白天的回應率明顯低於夜裡（各擲 1000 次）；
  - 循聲而去：按鈕只在有回應的時候出現、按了走到那一區、記憶過期後按鈕消失；
  - 到達後：母狼在那一區時遇上的機率提高；狼群那一側先出現標記、再往領域走才撞上；
  - 暴露：在邊界、領域裡嚎叫會讓那一群察覺；離得遠不會；
  - 沒有冷卻：連續嚎叫都可以。
- **模擬 `mate_howl_sim`**（自動玩家，每種策略 200 隻，從 2 歲玩到 4 歲）：
  - 策略：認真找（秋冬晨昏嚎叫、跟一隻的回應走）／偶爾嚎叫／不找；
  - 指標：第一次遇上母狼的天數與比例（一個秋冬內）、遇上後一季內配對、一年內不找也遇上、循聲接近狼群後撞上的比例、每天嚎叫次數與遇上的關係、挨餓天數；
  - 對照通過標準（測試目標，不是規則）：認真找 ≥ 80%、配對 50～70%、不找 30～50%、撞上狼群 20～50%（太低等於沒風險、太高等於懲罰，Claude Code 的假設）。
- **一生模擬 `life_pressure`**：挨餓、壽命不惡化；配對的歲數、有伴侶的比例和現在比。
- **既有的回歸**：`mate_rules`、`mate_pack_rules`、`black_pack_rules`、`territory_rules`、`encounter_matrix`、`check_keys`、`check_text`。
- **試玩清單**：加一項「用嚎叫找伴侶」：晨昏與白天各嚎幾次、跟著一隻的聲音走、跟著合聲走到看到標記時的決定。

## 6. 實作順序（Phase 1 內，每步做完都測試、提交）

1. 資料與狀態：離群母狼照季節在不在、出現的位置、每天的離開與走進、避開狼群領域；取消 7 天離開。
2. 嚎叫回應：回應的判定（距離、時段、季節、關係）、文字、知識頁的觀察；暴露的風險。
3. 循聲而去與到達後的探索結果；畫面（嚎叫的回應卡片、行動欄的按鈕）。
4. 自動玩家、模擬、回歸測試、試玩清單；對照通過標準校準。

## 7. 開始前需要使用者確認的事項

1. **黑狼一家要不要在 Phase 1 回應？** 森林裡除了地圖外的鄰群，主要的狼群就是黑狼一家。不回應的話，在森林嚎叫幾乎只會聽到母狼與遠方的鄰群，少了「這邊有一群」的判斷；回應的話，牠的風險規則照一般狼群（暴露、循聲過來）。Claude Code 建議：**回應**，照一般狼群處理（那隻黑狼單獨的回應留到 Phase 3）。
2. **方向用區域名稱**（「從溪流源頭那一帶傳來」）可以嗎？地圖資料沒有東西南北；要用方位的話，得先替每張地圖補區域的相對位置。Claude Code 建議：Phase 1 先用區域名稱＋遠近。
3. **母狼「每天離開這張地圖」的機率**（第 3 節的表）：取消 7 天之後，用這個代替「牠也在找、不會永遠等你」，關係好的幾乎不走。這樣可以嗎？還是 Phase 1 乾脆不讓牠離開（Phase 2 再做牠的活動）？
4. **徵兆卡要不要完全拿掉？** 現在母狼出現時會跳一張「聞到陌生母狼的氣味」的卡片。Phase 1 改成不跳，要靠嚎叫或探索才知道；但探索時仍有機會看到牠的足跡、氣味（這種線索不說是母狼，只說「一隻狼的足跡」）。
5. **嚎叫會不會驚動獵物？** 真實的狼嚎可能讓附近的獵物警覺，但目前沒有這條規則。Claude Code 建議：Phase 1 **不加**，避免嚎叫的代價太多；有需要再談。
6. **兩區外的回應怎麼循聲？** 建議「循著嚎聲而去」每次只走一步（往那個方向的相鄰區），到了再嚎或探索；不直接跨兩區。

以上確認後，再把 Phase 1 寫成 SPEC（寫入前會先給你看要寫的段落）。
