# 測試指南（2026-10-09 整理）

給 Claude Code 自己用的測試參考：把 QA-01～74 與開發過程中遇過的問題歸類成「容易出錯的地方」，整理每次改動要跑的檢查、回歸測試案例、headless 測試的寫法與模擬的基準值。使用者試玩用的清單在 `playtest-checklist.md`，兩份分工不同。

每次修完一個新的 QA，把它歸到下面的類別、在「回歸測試案例」加一列。

## 一、遇過的 bug 歸類（找問題時先想這幾類）

### A. 事件的先後與敘事順序（最常見）

同一個時段裡發生好幾件事時，紀錄、卡片、畫面的順序對不上。

### G. 640×360 的排版

試玩 2026-10-15 第 2 項：狩獵畫面換階段後狼和獵物的圖都不見（`_clear_children` 用 queue_free，舊按鈕在量高度時還在容器裡，被算成「放不下」而拿掉角色圖；改成刪除前先隱藏。`ui_check` 會報 HUNT_SPRITE_HIDDEN）。QA-02（行動紀錄被擠出視窗）、03（地圖按鈕的字被截掉）、04（除錯選單跑版）、27（一生回顧的長句）、76（Phase 2 的長說明、新戰鬥因素把開局與戰鬥畫面撐出 640）。雲端沒有畫面，用 `bash tools/ui_check.sh` 實際遊玩、量測元件位置並截圖；新增長文案或新按鈕時都要列進 `progress.md` 的目視確認。

### G3. 動物照比例（2026-10-13）

狩獵、戰鬥畫面用固定像素倍率畫角色（`AnimatedIcon.zoom`），對手乘上 `art.json` 的 `display_scale`（相對灰狼）。新增或重畫動物時要一起訂 `display_scale`：量待機格的實際高度，換算成目標高度（灰狼 30 像素 = 1）。沒寫的話成體是 1、幼獸是成體 × 0.7，圖的像素大小不一致時就會大小失真。

### G2. 組出來的翻譯鍵（QA-66、76）

`tr("prefix." + id)` 這類鍵 `check_keys.py` 只檢查得到用資料 ID 組的（地圖、區域、地形、避難）。因素組成的失敗原因（`reason.<因素>`）、事件結果等要靠 `tools/ui_check.sh` 跑出來；新增地形、因素、事件結果時，對應的文字一起寫。

遊玩時也會檢查（2026-10-16，`scripts/ui/TextWatch.gd`）：主畫面每 0.5 秒掃一次看得到的文字，紀錄（含照常過日子、自動遊玩時 GameState 送出的）每一行都檢查，規則同 `ui_check`（RAWKEY、PLACEHOLDER）。找到的記進試玩紀錄 `metrics.text_issues`（含地點、年齡、區域、是否照常過日子），除錯選單「試玩紀錄」也看得到；在編輯器裡遊玩時另外淡出「⚠ 畫面上有沒翻成文字的……」。讀試玩紀錄時先看這一欄。

### H. 開發流程本身的錯誤（給 Claude Code）

- **文件 patch 的錨點失效**：用 python 改文件時，一定用 `assert s.count(a)==1`；錨點找不到就停下來重找，不要用 `replace` 默默不改。
- **JSON 被整檔重新排版**：`json.dump` 會把整個 `art.json` 改成另一種格式。資料檔只用文字插入，改完再 `json.load` 驗證格式正確。
- **資料表裡的 `_xxx_comment` 鍵**：JSON 用 `_comment` 寫說明，但程式逐一走訪某個表（例如 `GameData.maps().keys()`）時會讀到字串而當掉（QA-75：山地、草原加進 `maps` 的說明讓 `ice_shortcuts()` 一進遊戲就報錯）。走訪的表在載入時拿掉非 Dictionary 的項目，或走訪時跳過 `_` 開頭的鍵；新增說明鍵後，用 headless 腳本跑一次會走訪該表的函式。
- **SPEC 引用區塊的縮排**：套用提案時，`  >` 這種有縮排的引用行容易漏掉，套用後 diff 檢查每一段。
- **GDScript**：`match` 不能用非常數的 pattern（改用 if）；headless 測試腳本的 `_process` 要寫成 `-> bool` 並在每條路徑回傳值；以 `-s` 執行時 autoload 還沒載入，不能直接引用 class_name 的列舉。
- **暫存檔**：測試腳本叫 `probe_tmp.gd`，用完刪掉（含 `.uid`）；`.gitignore` 已排除 `probe_tmp*`，但不要用 `git add -A` 加整個根目錄。
- **模擬看不出差異時**：先懷疑規則根本沒有作用（例如 hunt_levels 一開始顯示跟隨與短衝沒差別，原因是逃脫判定沒有用到跑法），不要直接調數值。
- **改一個機制會動到另一個的平衡**：例如「暴雨澆熄大火」讓一生遇到大火的機率從 85% 掉到 55%，要再補暴雨在乾季的倍率。改機率類的規則後，相關的模擬都要重跑。

## 二、每次改動要跑的檢查

1. `bash tools/godot_check.sh`（匯入、編譯、主場景啟動）。
2. `python3 tools/check_keys.py` 與 `python3 tools/check_text.py`（新增或改文案時；有「又、終於、比上次、從此、已經……」這類斷言時，把依據寫進 `docs/text-conditions.md`；後者檢查 {佔位} 有沒有被替換、半形標點、「我／玩家」，`--notes` 列出要人判斷的：苔原狼沒有單數版本、可能在苔原出現的森林字眼、敘事裡的遊戲用語）。
3. 改到的系統跑對應的模擬（見第五節），和基準值比較。
4. 寫 headless 測試走一次實際情境，印出文字讀一遍（A、C 類問題只有讀文字才看得出來）。
5. 對照第一節的 B 類問題問一次：跨地圖、離開再回來、換季、讀檔、事件進行中。
6. 改到遭遇、戰鬥、狩獵的流程或結果畫面：跑 `bash tools/run_sim.sh encounter_matrix`（R-68）；新增除錯觸發的事件時，加進腳本的 `_scenarios()`。
7. 有新畫面、長文案、新地形或新因素：跑 `bash tools/ui_check.sh`（xvfb 實際遊玩約 10 分鐘，找原始翻譯鍵、沒替換的佔位、超出畫面的元件，截圖在 /tmp/ui_check/），並列進 `progress.md` 的「待使用者目視確認」。

## 三、回歸測試案例

已修好的問題，之後改到相關系統時要確認沒有再壞。觸發方法優先用除錯選單（使用者可以照做），headless 測試用 `GameState.debug_*` 函式。

| 編號 | 情境 | 觸發 | 預期 |
| --- | --- | --- | --- |
| R-01 | 睡覺被灰熊、幼熊驚醒 | 在灰熊區域連續睡覺，或除錯「母熊」後睡覺 | 「你在好睡處睡下。夜裡你被驚醒了。你睜開眼，一頭幼熊…」；沒有「睡得很好」（QA-70） |
| R-02 | 睡醒卡片的順序 | 睡覺期間有渡鴉等事件 | 換日摘要（或季節卡片）→ 睡醒卡片 → 其他事件（QA-60） |
| R-03 | 遭遇中不換季 | 季末最後一天狩獵、進食 | 遭遇紀錄裡沒有「季節變換了」；換季只在睡覺時（QA-18、29） |
| R-04 | 跨地圖的事件 | 苔原暴風雪中移到森林 | 森林不收到風雪結束通知；回到苔原才跳「你離開的時候，苔原的暴風雪已經停了…」（QA-69） |

## 四、headless 測試的寫法

```gdscript
extends SceneTree
var f := 0
func _process(_d) -> bool:
	f += 1
	if f == 3: # 等 autoload 載入
		var gs = root.get_node("GameState")
		gs.new_game("forest_south")
		# 用 gs.debug_* 觸發情境，印出狀態或文字
		print("RESULT ", gs.life_log.get("adult_stats"))
		return true
	return f > 200 # 保險：卡住時自動結束
```

```bash
G=$(ls $HOME/.cache/godot/*/godot | tail -1)
timeout 120 $G --headless --path . -s probe_tmp.gd 2>&1 | grep "RESULT\|ERROR"
rm -f probe_tmp.gd probe_tmp.gd.uid
```

- 想看玩家實際讀到的文字：連接 `GameState.log_message` 訊號收集訊息，或讀 `life_log.recent_messages`。
- 機率類的規則：同一情境跑 200～1000 次統計，不要只跑一次。
- 截圖：`xvfb-run` 跑主場景再截圖，用來確認 640×360 的排版。

## 六、讀試玩紀錄

使用者在編輯器裡遊玩、死亡後，紀錄會存到 `playtest_logs/wolf_<時間>.json`（commit 後讀得到）。

- `life_log.potential`：成年時的巔峰上限；全是 55／90 代表次成年期被除錯跳過，不能拿來驗收成長。
- `life_log.adult_stats`、`adult_body`、`adult_bonus`：成年時的能力、體型描述、成年那一刻的成長。
- `metrics`（最上面）：遊玩分鐘、每天決策與事件數、最長平淡天數、選最高成功率的比例、1 秒內略過卡片的比例、各生命階段的分鐘數。比較兩份紀錄時先看這裡：選最高的比例接近 100% 代表選擇沒意義；略過比例高代表沒在讀；平淡天數長代表那一段無聊。
- `life_log.recent_combats`：最近 5 場戰鬥的逐回合紀錄（看戰鬥哪裡出問題）。
- `life_log.recent_messages`：主畫面最後約 40 段訊息（看文案與經過）。
- `life_log.tendency_history`、`decisions`：狩獵傾向的變化。
- 讀紀錄時順便檢查：有沒有原始鍵名、同一句重複、順序不通、名稱不對（第一節 A～D 類）。
