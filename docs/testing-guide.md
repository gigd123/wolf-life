# 測試指南（2026-10-09 整理）

給 Claude Code 自己用的測試參考：把 QA-01～74 與開發過程中遇過的問題歸類成「容易出錯的地方」，整理每次改動要跑的檢查、回歸測試案例、headless 測試的寫法與模擬的基準值。使用者試玩用的清單在 `playtest-checklist.md`，兩份分工不同。

每次修完一個新的 QA，把它歸到下面的類別、在「回歸測試案例」加一列。

## 一、遇過的 bug 歸類（找問題時先想這幾類）

### H. 開發流程本身的錯誤（給 Claude Code）

- **文件 patch 的錨點失效**：用 python 改文件時，一定用 `assert s.count(a)==1`；錨點找不到就停下來重找，不要用 `replace` 默默不改。
- **JSON 被整檔重新排版**：`json.dump` 會把整個 `art.json` 改成另一種格式。資料檔只用文字插入，改完再 `json.load` 驗證格式正確。
- **SPEC 引用區塊的縮排**：套用提案時，`  >` 這種有縮排的引用行容易漏掉，套用後 diff 檢查每一段。
- **GDScript**：`match` 不能用非常數的 pattern（改用 if）；headless 測試腳本的 `_process` 要寫成 `-> bool` 並在每條路徑回傳值；以 `-s` 執行時 autoload 還沒載入，不能直接引用 class_name 的列舉。
- **暫存檔**：測試腳本叫 `probe_tmp.gd`，用完刪掉（含 `.uid`）；`.gitignore` 已排除 `probe_tmp*`，但不要用 `git add -A` 加整個根目錄。
- **模擬看不出差異時**：先懷疑規則根本沒有作用（例如 hunt_levels 一開始顯示跟隨與短衝沒差別，原因是逃脫判定沒有用到跑法），不要直接調數值。
- **改一個機制會動到另一個的平衡**：例如「暴雨澆熄大火」讓一生遇到大火的機率從 85% 掉到 55%，要再補暴雨在乾季的倍率。改機率類的規則後，相關的模擬都要重跑。

## 二、每次改動要跑的檢查

1. `bash tools/godot_check.sh`（匯入、編譯、主場景啟動）。
2. `python3 tools/check_keys.py`（新增或改文案時）。
3. 改到的系統跑對應的模擬（見第五節），和基準值比較。
4. 寫 headless 測試走一次實際情境，印出文字讀一遍（A、C 類問題只有讀文字才看得出來）。
5. 對照第一節的 B 類問題問一次：跨地圖、離開再回來、換季、讀檔、事件進行中。
6. 有新畫面或長文案：列進 `progress.md` 的「待使用者目視確認」，必要時 xvfb 截圖。

## 四、headless 測試的寫法

```gdscript
extends SceneTree
var f := 0
func _process(_d) -> bool:
	f += 1
	if f == 3: # 等 autoload 載入
		var gs = root.get_node("GameState")
		gs.new_game("forest_south")
		# 用 gs.debug_* 觸發情境，印出狀態或文字
		print("RESULT ", gs.life_log.get("adult_stats"))
		return true
	return f > 200 # 保險：卡住時自動結束
```

```bash
G=$(ls $HOME/.cache/godot/*/godot | tail -1)
timeout 120 $G --headless --path . -s probe_tmp.gd 2>&1 | grep "RESULT\|ERROR"
rm -f probe_tmp.gd probe_tmp.gd.uid
```

- 想看玩家實際讀到的文字：連接 `GameState.log_message` 訊號收集訊息，或讀 `life_log.recent_messages`。
- 機率類的規則：同一情境跑 200～1000 次統計，不要只跑一次。
- 截圖：`xvfb-run` 跑主場景再截圖，用來確認 640×360 的排版。

## 六、讀試玩紀錄

使用者在編輯器裡遊玩、死亡後，紀錄會存到 `playtest_logs/wolf_<時間>.json`（commit 後讀得到）。

- `life_log.potential`：成年時的巔峰上限；全是 55／90 代表次成年期被除錯跳過，不能拿來驗收成長。
- `life_log.adult_stats`、`adult_body`、`adult_bonus`：成年時的能力、體型描述、成年那一刻的成長。
- `life_log.recent_combats`：最近 5 場戰鬥的逐回合紀錄（看戰鬥哪裡出問題）。
- `life_log.recent_messages`：主畫面最後約 40 段訊息（看文案與經過）。
- `life_log.tendency_history`、`decisions`：狩獵傾向的變化。
- 讀紀錄時順便檢查：有沒有原始鍵名、同一句重複、順序不通、名稱不對（第一節 A～D 類）。
